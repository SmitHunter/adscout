# AdScout M2 — Scoring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `uv run adscout report <snapshot_id>` prints a Winner Score 0–100 with a factor breakdown (value, thresholds, pass/fail chip, points), warnings and a monthly timeline. Unit tests pin the score against hand-computed values.

**Architecture:** A new pure `adscout.scoring` package. It takes `list[Ad]` plus the keyword, overrides and `now`, and returns a Pydantic `WinnerScore`, with no I/O. Relevance and creative grouping are computed on the fly at scoring time (the reserved `AdRow.relevant` and `creative_key` columns stay unused). Manual overrides live in a new `Exclusion` table. The CLI only loads data, calls `score_ads`, and renders.

**Tech Stack:** Python 3.12, Pydantic v2, SQLModel, Typer + Rich, pytest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-17-adscout-design.md` (decisions 1, 3, 4, 5, 6 and the Data model). Follow-ups: `docs/plans/2026-10-17-m1-followups.md` (M2 section, handled in Task 1).

## Global Constraints

- Python 3.12 / uv. mypy `strict` on `src/`. ruff `E,F,I,UP,B,SIM,RUF` clean. Tests are offline. Don't run `ruff format` over `docs/`.
- Scoring is pure: no DB, network or clock access inside `adscout.scoring`. `now: datetime` (aware UTC) and `tz: ZoneInfo` are always parameters.
- Weights: **Longevity 30, Creative volume 25, Angle diversity 25, Continuity 20.** Saturation is a warning, never points.
- Thresholds live only in `src/adscout/scoring/thresholds.py`, and the CLI displays them from there:
  - Longevity oldest-active-age days: `fail=30, pass_=90, full=180`.
  - Longevity share of ads ≥ 90 d: `fail=0.05, pass_=0.25, full=0.50`.
  - Continuity months with a new creative, out of the last 6: `fail=3, pass_=5, full=None`.
  - Volume distinct creatives: `fail=3, pass_=10, full=20`.
  - Angles distinct clusters: `fail=2, pass_=3, full=5`.
  - Saturation advertisers: `1–2 → "early"`, `3–15 → "healthy"`, `>15 → "crowded"`.
- Status rule (chips): `value < fail → "fail"` (red), `value >= pass_ → "pass"` (green), otherwise `"warn"` (amber). Angles in M2 are `"pending"` (grey).
- Ramp rule (0–1 factor score). This algorithm is not determined by the signature:
  - `v < fail → 0.0`
  - `fail ≤ v < pass_ → 0.3 + (H − 0.3) · (v − fail)/(pass_ − fail)`, where `H = 0.7` if `full` is set, else `1.0`
  - `full` set and `pass_ ≤ v < full → 0.7 + 0.3 · (v − pass_)/(full − pass_)`
  - `v ≥ full`, or `v ≥ pass_` when `full is None` → `1.0`
- Longevity score = `0.5 · ramp(oldest_active_days) + 0.5 · ramp(share_90d)`. Its status comes from `oldest_active_days` alone.
- Total = `round(100 · Σ(weight·score) / Σ(weight))` over the factors that are not pending. `provisional = True` whenever Angles is pending. Factor `points = round(weight · score, 1)`.
- Copy (exact): provisional badge `PROVISIONAL — angle analysis pending (M4)`; no relevant ads `No relevant ads — check the keyword or your exclusions.`; partial-data note for a snapshot with status `capped`/`blocked`/`cancelled`: `Partial data: this snapshot stopped early ({status}).`
- Commits end with a blank line + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Every ad filtered out (or zero ads):** the score is 0, every factor shows value 0 with status fail, and the warning `No relevant ads — …` appears, with no ZeroDivisionError. Tests in Tasks 4 and 5.
2. **Keyword with punctuation, unicode or plural forms** (`knee-brace`, `crème`, `posture correctors`): the tokens match `knee brace sleeve`, `CRÈME`, and `posture corrector`. Tests in Task 2.
3. **An ad whose start date is after `now`** (clock skew or a timezone edge): its age clamps to 0 days, never negative. It still counts toward its month for continuity. Test in Task 4.
4. **Override precedence:** an ad-level include beats an advertiser-level exclude, which beats the keyword filter. Overrides are keyed by the normalised keyword, so a re-run of the same search keeps them. Tests in Task 2.
5. **Partial snapshots** (`capped`/`blocked`): the report still renders, shows the partial-data note, and exits 0. Test in Task 6.

### Task 2: Relevance filter + Exclusion overrides

**Interfaces:**
- Produces (`scoring/relevance.py`):
  - `tokens(text: str) -> list[str]`: NFKD-fold accents, lowercase, split on non-alphanumerics, then simple stem: strip a trailing `"es"` when the token is longer than 4 and ends in `"ses"|"xes"|"ches"|"shes"`; otherwise strip a trailing `"s"` when the token is longer than 3 and doesn't end in `"ss"`.
  - `normalise_keyword(keyword: str) -> str`: `" ".join(tokens(keyword))` (the override key).
  - `is_keyword_match(ad: Ad, keyword: str) -> bool`: every keyword token is present in the token set of `body + title + link_caption + link_url`.
  - `Override(BaseModel)`: `scope: Literal["ad", "advertiser"]`, `target_id: str`, `mode: Literal["exclude", "include"]`.
  - `RelevanceDecision(BaseModel)`: `ad_archive_id: str`, `relevant: bool`, `reason: Literal["keyword", "no_keyword", "ad_override", "advertiser_override"]`.
  - `decide_relevance(ads: list[Ad], keyword: str, overrides: list[Override]) -> dict[str, RelevanceDecision]`: precedence is ad override > advertiser override (matched on `advertiser_key`) > keyword match.
- Produces (db):
  - Table `Exclusion`: `id`, `keyword_norm: str` (index), `scope`, `target_id`, `mode`, `created_at` (UTC), with a unique `(keyword_norm, scope, target_id)`.
  - `set_override(session, keyword: str, scope, target_id: str, mode) -> None` (upsert).
  - `clear_override(session, keyword: str, scope, target_id: str) -> bool`.
  - `list_overrides(session, keyword: str) -> list[Override]`.
  - All three normalise via `normalise_keyword`.

## Rulings in this plan (made by Claude; cheap to change)

1. The ramp anchors (0.3 at fail, 0.7 at pass, 1.0 at full) and the share-of-ads ramp (5 / 25 / 50 %) are my choices. The spec gives thresholds but not the curve.
2. Continuity counts calendar months in the display timezone, and includes the current partial month.
3. Relevance and creative keys are computed at report time, not stored, so changing an override never needs a migration.
4. Overrides are keyed by the normalised keyword, so `Posture Correctors` and `posture corrector` share them.
