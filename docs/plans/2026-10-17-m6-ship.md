# AdScout M6 — Ship It Public Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. UI/visual tasks load `frontend-design:frontend-design` first.

**Goal:** The repo is ready to publish as `github.com/SmitHunter/adscout`. That means:
- **README:** a hero screenshot, a ~20 s demo GIF, a Mermaid architecture diagram, setup in 3 commands, a scoring explainer and the disclaimer.
- **Repo files:** MIT license, CI (lint + tests on Linux/Windows/macOS), a gitleaks secrets scan, and issue/PR templates.
- **Demo mode:** `uv run adscout demo` lets a visitor explore a fully populated app without touching Meta. Every public image uses that **synthetic** data, so no third-party ads are republished.

Creating the GitHub repo and pushing is **not** part of this plan. The controller asks the user before publishing.

**Architecture:**
- **Demo:** a demo data directory (`data-demo/`), seeded by a deterministic generator. It holds synthetic products, advertisers, ad copy, Pillow-drawn product images, analyses, watch history and alerts. `adscout demo` serves it read-mostly, with searches and analysis disabled.
- **Media:** screenshots and the GIF are produced by scripts from demo mode, so they are reproducible.
- **Hardening:** this task clears the follow-ups tagged M6.

**Tech Stack:** existing stack; GitHub Actions; gitleaks-action; Pillow (GIF assembly).

**Spec:** `docs/build-prompt.md` § "M6 – Ship it public" and "Quality bar". Follow-ups: `docs/plans/2026-10-17-m1-followups.md`, sections tagged M6.

  1. `uv sync`
  2. `npm --prefix web ci && npm --prefix web run build`
  3. `uv run adscout` (`uv run adscout demo` to explore with sample data first)

  Prerequisites line: Python 3.12 via uv, Node 22.22+, and `uv run playwright install chromium` for live searches.
- **License:** MIT, copyright holder `SmitHunter`, year 2026.
- **Commits** end with a blank line + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

### Task 1: M6 hardening batch

**Files:** as needed across `src/` and `web/src/`, with tests.

The batch (each item with a test where behaviour changes):
- **Media downloads:** only `https://` URLs are fetched (others skipped with a warning). `Content-Type` is cross-checked against `MediaItem.type`: an image item never stores a video and vice versa.
- **Unstarted SSE generator leak:** fix it.
- **Unknown API routes:** non-GET to an unknown `/api/*` returns 404, not 405.
- **Web client errors:** a non-JSON error body shows `Request failed ({status}).`, never raw HTML. `response.text()` goes inside the try.
- **Font token:** replace `[font-stretch:87%]` with the `font-dense` token everywhere.
- **Sonner:** toast styles are fully tokenised.
- **a11y:**
  - `<time>` tooltip triggers respond to Enter.
  - The live region is always mounted.
  - Confirm dialogs get Esc/focus tests.
  - The `fieldFor` fallback is tested.
- **Recharts lazy-load:** lazy-load the chart bundles so the main chunk is < 500 kB and the build warning is gone.
- **Analyze confirm copy:** `This sends {n} creatives to Claude ({backend_label}) and uses your quota. Continue?`
- **Claude CLI isolation:** run the analysis subprocess with `--setting-sources ""` (or the equivalent flag the installed `claude --help` lists) so the user's own hooks and settings don't apply. Verify the flag exists. If it doesn't, document it and skip.
- **mypy over tests:** fix the existing errors so `uv run mypy src tests` is clean. CI will run it.
- **`get_source` tests:** use `tmp_path` data dirs.
- **`screenshots.py`:** refuse a non-loopback `--base`.
- [ ] TDD per item → implement → full checks → commit `fix: M6 hardening batch` (split into 2–3 commits if large).

### Task 2: Demo mode (`adscout demo`)

**Files:**
- Create: `src/adscout/demo/{__init__.py,generator.py,images.py}`, `tests/demo/test_generator.py`
- Modify: `src/adscout/cli.py`, `src/adscout/api/{app.py,routes.py,watch_routes.py}`, `web/src/...` (demo banner)

**Interfaces:**
- **Generator:**
  - `generate_demo(data_dir: Path, seed: int = 7, now: datetime | None = None) -> None` is deterministic and idempotent, and rebuilds when `--reset` is passed.
  - It creates 4 products, each with a keyword snapshot (`posture brace`, `heated eye mask`, `magnetic phone mount`, `led face mask`), with 40–180 ads across 6–30 invented advertisers.
  - Start dates are spread so the scores span strong, crowded, weak and early.
  - Each snapshot gets an `Analysis` (`backend="demo"`, hand-written verdicts, angles, hooks and offers; a few ads are flagged off-topic).
  - 2 watch items carry 21 days of daily snapshots each (one scaling, one fading), 2 alerts (1 unread), and 1 capped point.
  - Images are Pillow-drawn, 512×512: abstract product silhouettes with a palette per brand and a short invented brand wordmark. They are stored as media blobs with phashes; a few ads share an image to show variants. Videos are posters only, marked as video, with `local_path` None. The gallery shows the poster and play is disabled.
- **`adscout demo [--reset] [--port 8788] [--no-open]`:**
  - Uses `data_dir = ./data-demo` (gitignored), generates it if missing, and serves with `demo=True`.
  - Its server lock and port file are separate from the real app's, so both can run.
- **Demo flag effects:**
  - `create_app(..., demo=True)` makes these return 403 with the demo copy: POST `/api/searches`, POST `/api/watch/{id}/run`, POST `/api/browser/open`, POST `/api/snapshots/{id}/analysis`.
  - The scheduler does not start.
  - `GET /api/settings` includes `demo: true`.
  - The web shows a slim top banner `Demo data. Nothing here is real. Run uv run adscout to search for real.`, and disabled controls carry the copy as a tooltip.
- [ ] **Step 1: Failing tests:**
  - `test_generate_is_deterministic` (same seed → same rows and image hashes)
  - `test_brands_avoid_denylist`
  - `test_scores_span_bands` (at least one ≥ 70, one 40–69, one < 40)
  - `test_watch_history_has_capped_point_and_alerts`
  - `test_demo_blocks_live_actions` (4 routes → 403 copy)
  - `test_demo_no_scheduler`
  - CLI `test_demo_uses_separate_data_dir_and_lock`
  - web `demo banner and disabled search`
- [ ] **Step 2–4:** FAIL → implement → PASS. Also run `uv run adscout demo --no-open` and curl the report for each snapshot (200).
- [ ] **Step 5:** Commit `feat: demo mode with synthetic data`.

  3. Scroll to the angles.
  4. Open the gallery.

  6. Open the watchlist and a trend.
